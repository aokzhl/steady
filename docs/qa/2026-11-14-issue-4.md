# Issue #4 — ordinary projects

## Scope and behavior

Issue: https://github.com/aokzhl/steady/issues/4

Ordinary projects have a required trimmed title and optional small color marker. The sidebar lists projects and counts all open tasks assigned to each project. Clicking a project filters the existing Today list; All tasks resets project context and groups open tasks by their current project. Period/calendar navigation remains owned by its later slice.

The sidebar plus opens native project creation. The selected project header pencil and sidebar context menu rename it. Project creation immediately updates sidebar and task pickers; rename retains its UUID and updates all displays. No project type, completion, timer, archive or report actions are added.

Task creation and task details expose one optional project picker including Без проекта. A fresh draft explicitly starts with the selected project, while an existing draft retains its own choice when navigating elsewhere. Project selection is stored on the task and durable creation draft; consuming a draft preserves its choice. Details preserve failed input and allow retry/discard through the existing editor error flow.

SQLite migrates v2 to v3 transactionally with a projects table and nullable foreign keys on tasks/draft. Existing task and occurrence UUIDs, calendar dates, completion instants, priority and drafts are unchanged. Actual timestamps remain Unix instants (UTC); planned days remain date strings.

## Native QA handoff

Native launch and independent Standards/Spec reviews are coordinated by the root agent after integration. Verify with an isolated STEADY_DATA_DIRECTORY:

1. Create projects with/without a color. Observe immediate sidebar and picker entries.
2. Select a project, create a task, and inspect its explicit project default. Override to Без проекта and another project.
3. Begin a nonempty draft with a project, close creation, change context, reopen; draft choice remains. Also open an empty form in project A, explicitly choose Без проекта, close, switch to project B, reopen, quit/reopen: Без проекта remains. An untouched empty form in All tasks is not persisted.
4. Change project in task details, rename a project via header or context menu, and check sidebar/list/pickers.

## Review regression: explicit no-project choice

Root native review found that an empty form explicitly changed to Без проекта was indistinguishable from an untouched blank form. Closing erased that choice; reopening seeded the current project again. The regression first failed at the public TaskWorkspace/SQLite reopening boundary with `creationDraft → nil`. The fix persists `CreationDraft.projectWasChosen` in the unshipped v3 migration, uses shared `CreationDraft.isEmpty` for model/storage/editor decisions, and sets the flag on explicit project picker input. Discard and successful creation reset it. Untouched blank drafts still are not persisted.

No app launch was performed in the implementer worktree to avoid competing with root native validation. Project context restoration is part of later navigation persistence; this slice retains the existing Today period.
