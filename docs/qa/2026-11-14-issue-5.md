# Issue #5 — global labels

Issue: https://github.com/aokzhl/steady/issues/5

## Delivered behavior

Labels are global across projects, with a required trimmed title and optional small color marker using the existing color palette. The sidebar lists labels below projects; plus creates a label. Selecting a label opens its context across projects within the current period. Header pencil/trash and sidebar context menus rename/delete. All tasks resets the private context. The existing Today/Tomorrow/All period and nullable planned dates coexist with label context; combined project/label and any/all conditions remain in their separate slice.

Creation/details have a multi-selection label popover with case-insensitive search and create-and-assign. Selected names are visible before saving; a fresh label context preselects that label, while an existing draft retains its selection. Explicitly removing all labels from an empty draft persists that choice through closure/restart, paralleling the existing explicit no-project behavior. Untouched blank forms remain unsaved. Task rows display at most two label chips and +N, with all names in the help/accessibility text.

Renaming preserves label UUID and updates all displays. Unicode case folding plus canonical normalization protects against duplicates caused by capitalization (including Cyrillic); the database also enforces uniqueness for active names. Empty/invalid input and storage errors preserve input for retry.

Deleting removes the label from the active list, pickers, effective task/draft associations and active label context. A visible named deletion notice offers Undo, including after restart. Tombstones retain associations only for restoration; public records expose active labels only. Undo restores identities and associations without changing task occurrences, dates or completion instants. Unrelated draft title, note, priority and project saves preserve hidden associations for Undo. Explicit reassignment after deletion replaces the old associations, including an explicitly empty selection; undo does not overwrite those later choices. If an active label has taken the deleted name, undo reports the name collision until the active label is renamed, keeping both records and the undo action.
