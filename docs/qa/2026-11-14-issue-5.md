# Issue #5 — global labels

Issue: https://github.com/aokzhl/steady/issues/5

## Delivered behavior

Labels are global across projects, with a required trimmed title and optional small color marker using the existing color palette. The sidebar lists labels below projects; plus creates a label. Selecting a label opens its Today context across projects. Header pencil/trash and sidebar context menus rename/delete. All tasks resets the private context. Combined project/label/period filters and any/all conditions remain in their separate slice.

Creation/details have a multi-selection label popover with case-insensitive search and create-and-assign. Selected names are visible before saving; a fresh label context preselects that label, while an existing draft retains its selection. Explicitly removing all labels from an empty draft persists that choice through closure/restart, paralleling the existing explicit no-project behavior. Untouched blank forms remain unsaved. Task rows display at most two label chips and +N, with all names in the help/accessibility text.

Renaming preserves label UUID and updates all displays. Unicode case folding plus canonical normalization protects against duplicates caused by capitalization (including Cyrillic); the database also enforces uniqueness for active names. Empty/invalid input and storage errors preserve input for retry.

Deleting removes the label from the active list, pickers, effective task/draft associations and active label context. A visible named deletion notice offers Undo, including after restart. Tombstones retain associations only for restoration; public records expose active labels only. Undo restores identities and associations without changing task occurrences, dates or completion instants. Explicit reassignment after deletion replaces the old associations; undo does not overwrite those later choices. If an active label has taken the deleted name, undo reports the name collision until the active label is renamed, keeping both records and the undo action.

## Storage and verification

Transactional v4 → v5 migration adds labels, task/draft join tables, and an explicit label-choice draft flag. Shipped v3 project and v4 rich-note migrations remain unchanged. Prior project assignments, projectWasChosen, rich-note RTF/plain text and draft note fields remain intact. Actual created/deleted instants are Unix timestamps (UTC); planned days remain calendar dates. No API.

Approved automated boundary: public TaskWorkspace with real temporary SQLite and reopening. Create/rename, multiple assignments/drafts, and delete/undo were separate red-green vertical slices. Additional regressions cover v4 migration with existing rich notes, write failures/retry, and undo name/assignment conflicts.

3. Assign the same label to tasks in different projects and a task without a project; select that label in the sidebar.
4. In label context open a fresh draft. Verify its visible default; uncheck every label while title is empty, close, switch context and reopen/restart. Selection remains explicitly empty.
5. Rename the selected label, then delete it. Verify all sidebar/list/picker associations update, tasks/completion/project stay intact, active heading resets and the named Undo notice appears.
6. Undo and reopen offline; verify label and relationships return. Repeat deletion/restart/undo. Optionally rename a replacement with the same title to resolve an undo collision.
7. Recheck project counts, project creation/rename, explicit Без проекта draft choice, task title/priority, completion/undo and durable drafts from #2–4.
