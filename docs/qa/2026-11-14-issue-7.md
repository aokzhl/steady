# Issue #7 — one-off planning

Issue: https://github.com/aokzhl/steady/issues/7

## Behavior and storage

Creation and task details offer Сегодня, Завтра, Выбрать день and Без даты. The initial list context remains Сегодня. A compact Все / Сегодня / Завтра control makes undated and future tasks accessible and supplies concrete creation defaults for the two daily contexts. General creation through TaskWorkspace.createTask defaults to nil plannedDay; callers in daily contexts pass the day explicitly. Full period/filter navigation and the month calendar remain later slices.

Today displays open past plans in Ранее запланировано, followed by today's tasks. All displays open tasks across all dates and without a date. Completion remains a separate instant and completed tasks remain accessible. Changing the plan updates the same occurrence and retains task UUID, occurrence UUID and completedAt. Existing tests that require today's date now pass workspace.today explicitly; their date, identity and persistence assertions are retained.

Days are validated Gregorian yyyy-MM-dd calendar dates, with nil meaning no date. Relative Today/Tomorrow resolve using the injectable clock and current calendar zone, using calendar day arithmetic across daylight saving transitions. Persisted dates are never shifted when the current zone changes. New/rescheduled plans retain the current zone as separate metadata; completion is still a UTC Unix instant. This adds no time of day or deadline.

The durable draft persists plannedDay and dayWasChosen, including explicit Без даты on an otherwise empty draft. The public prepareCreationDraft applies daily/general defaults until a day is explicitly chosen, retaining explicit day/no-date choices across contexts and reopening. Existing project draft choices remain intact. Failed schedule writes keep saved records unchanged; detail editing retains the proposed input for retry or discard.

SQLite v5 transactionally rebuilds task_occurrences with nullable planned_day, copies existing facts, and adds the draft fields. This branch is rebased onto main db3202a. Shipped project v3 and note v4 migrations are unchanged; scheduling is the separate v5 migration. Both task and draft note RTF bytes/plain text are preserved, including through creation-context preparation.
