# Нативная приёмка Issue #2

Дата: 14 ноября 2026 года. Окружение: macOS 26.6.2 arm64, Apple Swift 6.2.3, Command Line Tools. Deployment target — macOS 14; отдельный физический Mac с macOS 14 не использовался.

Приложение собрано как Steady.app и запущено с STEADY_DATA_DIRECTORY в уникальной временной папке. Обычная гостевая база не использовалась для тестовых записей. Взаимодействия выполнялись через нативные элементы доступности и клавиатуру.

## Проверенные сценарии

| Действие | Наблюдаемый результат |
| --- | --- |
| Первый запуск с пустыми данными | Сегодня/список, гость, доступное создание, понятное пустое состояние |
| Добавить задачу | Форма справа, название, подставленное Сегодня и Без проекта |
| Сохранить непустое название | Задача появляется в списке, форма закрывается |
| Выполнить | Задача перемещается в Выполнено сегодня, доступна отмена |
| Полный выход и повторный запуск с той же папкой | Название, выполненное состояние и идентификатор выполнения в accessibilityIdentifier сохранились |
| Отменить выполнение | Та же задача возвращается в открытые, идентификатор остаётся прежним |
| Сделать временную папку данных недоступной и сохранить | Введённое название остаётся в форме, видно сообщение и Повторить сохранение; прежняя задача остаётся в списке |
| Восстановить папку и повторить | Запись появляется один раз, форма закрывается, прежняя запись сохранена |
| Cmd+N и ввод без мыши | Открывается форма, фокус находится в названии, текст вводится |
| Escape, затем Cmd+N | Незавершённый текст восстанавливается из памяти процесса |

В ходе проверки исправлен первоначальный дефект фокуса: onAppear назначал фокус до готовности текстового поля. Default focus и назначение после следующего прохода main actor проверены повторным реальным вводом без мыши.

## Автоматические проверки

Swift Testing, публичный TaskWorkspace и настоящие временные SQLite: создание/повторное открытие, пустой ввод, отдельные UUID, локальный день/часовой пояс, выполнение/отмена, идемпотентная отметка времени, ошибка записи с повтором, отдельные гостевые пространства, повреждённый файл и неизвестная более новая схема. Проверки не читают внутренние таблицы приложения для утверждения результата.

Первоначальная проверка сохранения падала из-за отсутствия записи после открытия нового TaskWorkspace. После реализации транзакционного хранения она прошла. Проверки пустого ввода, отметки и недопустимого NUL также запускались падающими перед реализацией соответствующего поведения.

Ошибки настройки Testing в CLT устранены в общей тестовой команде: добавлены пути к встроенным фреймворку/макросам и отключён некомплектный cross-import overlay только для тестовой сборки.

## Исправления после ревью

- Standards: смена дня не гарантировала перерисовку при неизменных строках SQLite. Контекст локального дня/часового пояса теперь наблюдаемый; списки текущего дня вычисляются через прикладной интерфейс.
- Spec: календарь сохранял часовой пояс момента запуска. Источник календаря теперь читается при обновлении и создании; смена системной зоны вызывает обновление. Сохранённые плановые дни прежних задач не переписываются.
- Перед исправлением отдельно воспроизведены падающие проверки отсутствия уведомления после полуночи и неверного дня после изменения зоны. После исправления они прошли. Дополнительно проверена смена зоны, при которой строка текущей даты не меняется, но состав Выполнено сегодня меняется.
