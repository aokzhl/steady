# Issue #2 — первый локальный сценарий Steady

Источник: https://github.com/aokzhl/steady/issues/2. Базовая точка Git: `0984047`.

Пользователь подтвердил техническую основу и границы проверки 14 ноября 2026 года.

## Принятые решения

- macOS 14+, Swift 6.2, SwiftUI/AppKit. Swift Package Manager собирает исполняемый клиент; mise предоставляет общие команды. Для этого среза достаточно Command Line Tools.
- SQLite из macOS SDK, без внешних зависимостей. Первая схема создаётся транзакционной миграцией; неизвестная более новая версия не перезаписывается.
- Локальные данные гостя располагаются отдельно в Application Support/Steady/guest. Будущие аккаунты не используют гостевое пространство неявно.
- Задача и конкретное выполнение имеют отдельные UUID. Плановый день сохраняется как календарная дата с часовым поясом; выполнение — как точный момент, отмена очищает только эту отметку. Длительность без инструмента времени не создаётся.
- Единственная прикладная граница для автоматических проверок — команды TaskWorkspace и доступные через него задачи. Тесты создают настоящую SQLite во временной папке и повторно открывают её; внутренние SQL-таблицы не являются интерфейсом тестов.
- Внешний вид, ввод, выполнение и повторный запуск дополнительно проверяются в нативном приложении с отдельными тестовыми данными.

## Поведение среза

Гость видит Сегодня/список и создаёт задачу с непустым названием. В создании справа подставлен сегодняшний день. После сохранения задача появляется в списке. Чекбокс выполняет выбранное выполнение и позволяет отменить отметку. После перезапуска сохраняются название, оба UUID, день и состояние.

При ошибке открытия или записи приложение показывает доступное действие повтора. Введённое название сохраняется в памяти, пока операция не завершена успешно. Закрытие формы само по себе не очищает ввод; долговременное восстановление черновика относится к следующему тикету.

Компоновка следует макету от 11 ноября: графитовая тема, сиреневый акцент, боковая панель, период над списком, создание справа. Возможности проектов, поиска, календаря и инструментов времени добавляются последующими тикетами.

## Порядок реализации и проверки

1. Падающий тест создания → повторного открытия, затем устойчивое сохранение.
2. Проверки пустого ввода, отдельных идентичностей и планового дня.
3. Падающий тест выполнения/отмены → восстановление отметки без потери идентичностей.
4. Проверки настоящей ошибки записи и безопасного открытия/миграции.
5. Нативное окно и сборка запускаемой .app через mise; проверка реального ввода и перезапуска.
6. Полный набор проверок, ревью Standards и Spec относительно базового коммита, исправления и коммит реализации.

Не входят в этот тикет: backend, аккаунты, инструменты времени, проекты/метки, note, повторения и полный набор фильтров.
