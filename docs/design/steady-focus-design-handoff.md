# Steady — подробные требования дизайна

Дата исходного разбора: 6 ноября 2026 года. Принятие дизайна: **7 ноября 2026 года**.

**Актуализировано 2026-11-11:** [текущий дизайн](steady-current-design.md) и `steady-tasks-projects-refined.html` заменяют старые A/B/C в вопросах компоновки. Периоды находятся над списком, инструменты доступны через одну кнопку с меню, создание открывается справа, отчёт имеет Сводку / Хронологию. В MVP только общие задачи; прежний снимок остаётся архивом.

**Уточнение 2026-11-09:** пользовательское название — Steady, Focus — инструмент внутри приложения. Тренировки и исламское направление — будущие возможности специализированных проектов, согласно [ADR-0008](../adr/0008-unified-steady-and-project-types.md). Подробный разбор ниже описывает принятый MVP задач и фокуса; исторические упоминания Focus не означают отдельного приложения.

**Дополнение 2026-11-10 с компоновкой от 11 ноября:** общие задачи получают необязательный выбор Таймер / Помодоро / Секундомер через одну кнопку с меню. Использованный инструмент и фактически учтённое время сохраняются для истории/отчётов. Подходы/вес/повторы и специализированные проекты разбираются позже.

**Статус:** текущий дизайн принят пользователем как основа реализации с допустимыми мелкими недочётами. [Фиксация v1, реестр требований и точный снимок макетов](steady-focus-design-baseline.md). [Обновлённый MVP](../MVP.md) задаёт объём первой версии; новый цикл выбора дизайна не требуется.

**Происхождение решений:** раздел 1 — прямые подтверждения пользователя; раздел 2 — ответы, которые ассистент выбрал по поручению пользователя вместо продолжения интервью. После принятия результата они служат рабочими решениями дизайна в пределах MVP. Формулировка «Рекомендую» сохранена как история авторства и не означает необходимость повторного опроса. Отдельный срок R08, расширенные повторы R28, библиотека фоновых звуков R33 и редактирование синхронизированного фокуса R48 не входят в MVP. Это требования к будущей реализации, а не утверждение о готовом приложении.

**Последнее уточнение пользователя во время генерации:** из MVP убран блок количественной цели/прогресса — «4 из 10 страниц», полоса, ручное значение и «+1», недельная полоса отметок. Количественные цели и автозавершение по ним отложены после MVP, включая минутные цели. Остаются выполнение задачи, счётчик подзадач, расписание повторений и фактическое время помодоро в истории/отчёте. Пример блока: [скриншот исключённого прогресса](../../design/steady-focus/references/deferred-progress-block.png).

**Плотность:** использовать актуальный макет как ориентир, сохраняя компактность, читаемость и доступные области нажатия. Старый ориентир строк 40–44 px относился к предыдущим вариантам и больше не задаёт фиксированную высоту. Три переключаемых варианта не являются требованием продукта.

Источники: [решения интервью и ответы агентов](../research/steady-design-agent-qa.md), [проверка установленного Focus To-Do](../research/focus-to-do-installed-review.md), [глоссарий](../../GLOSSARY.md), [референс порядка деталей от пользователя](../../design/steady-focus/references/task-details-reference.png). Актуальный [MVP](../MVP.md) обновлён по принятому дизайну и определяет границы реализации; этот документ уточняет поведение. Ранний агентский вариант календаря с полосой недели заменён месячной сеткой. Возможности конкурента не считаются автоматически требованиями Steady.

## 1. Подтверждено пользователем

### Представления и навигация

- Нативный Steady для macOS; спокойный графитовый интерфейс в духе macOS, чёткая типографика, тонкие разделители, сиреневый акцент и линейные иконки. Цвета проектов и меток — небольшие маркеры.
- Одни задачи доступны в двух представлениях: **Список / Календарь**. Переключение не создаёт копий.
- Календарь — **сетка месяца**, задачи внутри дней, без назначения часов. Нажатие задачи открывает детали; «Ещё N» открывает задачи дня.
- Боковая панель скрывается: поиск, **Все задачи, Отчёт**, ниже проекты и метки. **Все / Сегодня / Завтра / Ещё → Эта неделя / Этот месяц / Выполненные** — фильтры над списком. Список сгруппирован по проектам; дела без проекта и просроченные доступны отдельно.
- Общие разделы охватывают все проекты. Внутри проекта или метки свой переключатель периода: Все / Сегодня / Завтра / Ещё. Период сохраняется между проектами и метками.
- «Ещё» раскрывается по наведению или нажатию, доступно с клавиатуры. Применение периода происходит после выбора пункта. Контекст явно виден: «Ислам · Этот месяц».
- Строки: отметка выполнения, название, одна кнопка меню инструментов, краткие дата/проект/метки, счётчик подзадач. Выбранный проект не дублируется в каждой строке; длинный набор меток сворачивается в «+N».

### Задачи, проекты, заметки

- Привычка — задача с частотой повторения. Есть разовые задачи, повторы по выбранным дням и один раз в неделю в любой день. Каждый повтор имеет свои отметки выполнения; пропуски не накапливают долг. Разовая задача остаётся открытой.
- У задачи один необязательный проект и несколько необязательных общих меток. Проект — контейнер с результатами и суммарным временем, без собственного таймера и отметки выполнения; его можно архивировать.
- Подзадачи добавляются и при создании. Они независимо выполняются, могут иметь таймер, наследуют проект родителя и его параметры помодоро до переопределения. Метки и заметки не наследуются. Повторы подзадач следуют повтору родителя.
- Родитель включает своё время и время подзадач; общий отчёт считает каждый отрезок один раз. Выполнение родителя не завершает детей и не останавливает их активный таймер.
- Отчёты используют актуальные проект и метки для всей истории задачи. Переклассификация не меняет даты, длительности и факты выполнения.
- Количественные цели (страницы, минуты, повторения и другие единицы), их ввод/полоса прогресса и недельные отметки исключены из MVP последним решением пользователя. Предыдущие договорённости о целях относятся к возможной версии после MVP.
- Создание открывается справа: название, Расписание, Проект, Метки, Инструменты, Note и Подзадачи доступны до сохранения. Расписание объединяет день/повтор; контекст подставляется и редактируется, доступны Без даты и Без проекта.
- Детали используют текущую правую панель: метки, параметры расписания/проекта/инструментов, подзадачи, заметка и история запусков. Активная сессия управляется общей нижней панелью. Наблюдаемое поле Приоритет описано отдельно в текущем дизайне; его сортировочные правила не утверждены.
- **Note:** отдельная многострочная заметка у задачи и подзадачи, ссылки и простое форматирование — списки, жирный текст, выделение. Редактирование прямо в деталях, автосохранение. Повторы одной задачи используют общую заметку. Отдельные заметки к результату дня пока не включены.

### Фокус, монобровь и факт

- По умолчанию **25 / 5 / 15 минут, длинный отдых после 4 помодоро**. Параметры можно менять при создании задачи; подзадача может переопределить наследуемые значения. Общий профиль от этого не меняется.
- Отдельные автозапуски отдыха и следующего фокуса, оба выключены по умолчанию. Изменение профиля — для следующих запусков.
- Одна активная локальная сессия, включая паузу и отдых. При ней запуск другой задачи недоступен с переходом к текущей. Просмотр другой задачи не меняет владельца таймера. Есть запуск профиля без задачи.
- «Выполнить» у владельца таймера сохраняет работу и завершает его сессию; «Стоп» сохраняет работу, не выполняя задачу. Завершение родителя при активном ребёнке не останавливает ребёнка. Автозавершения по количественной цели в MVP нет.
- Во время фокуса можно менять остаток без остановки/сброса: **−20…+20 минут, шаг 1**, с предварительным результатом. Нажатие выбранного приращения повторяет его. Меняется текущая сессия, а не задача/профиль.
- Монобровь обязательна. Свёрнута: время/статус. При наведении: сверху задача/подзадача и профиль, в центре время и приращение, снизу пауза/продолжение, отдых/возврат, остановка, открытие окна. Окно и панель согласованы, панель работает при скрытом окне.
- Сон/блокировка — пауза; перезапуск — восстановление на паузе. Активный таймер между устройствами не синхронизируется. Результаты сначала сохраняются локально, затем доставляются через очередь.
- Для всех задач нужна история с фактическими датами и временем: работа с таймером — начало/конец и реальный фокус; без таймера — момент завершения без придуманной длительности. Напоминаний о задачах нет.

## 2. Самостоятельный разбор вопросов и рабочие ответы ассистента

Это самостоятельный проход по всем основным веткам дизайна. Ответы R01–R52 уточняют поведение макета; уже подтверждённые правила не переоткрываются.

### Навигация и фильтры

#### R01. Что открывается при запуске?

**Рекомендую:** при первом запуске — «Сегодня», список. Затем восстанавливать последний экран, фильтры, выбранную задачу и состояние боковой панели. Относительное «Сегодня» остаётся сегодняшним днём; активная сессия всегда доступна независимо от восстановленного экрана.

#### R02. Где находятся поиск, отчёт и настройки?

**Актуальная компоновка:** поиск и Отчёт в боковой панели, Добавить задачу в рабочей области, настройки/аккаунт в шапке окна. Выполненные — фильтр списка, отчёт показывает выполнение и время. Боковую панель можно вернуть кнопкой окна.

#### R03. В «Все задачи» входят выполненные?

**Рекомендую:** по умолчанию показывать открытые дела всех дат и без даты. Выполненные доступны отдельным разделом и переключателем «Показать выполненные» внутри текущего контекста. Повторяющаяся задача в общем списке представлена текущим/ближайшим выполнением, а не бесконечным перечнем будущих дат.

#### R04. Как совместить проект, несколько меток и период?

**Рекомендую:** проект и период ограничивают выборку одновременно; несколько меток по умолчанию означают «любая из выбранных», с явной подписью. Дополнительный режим «все выбранные» доступен в фильтре. Родитель неподходящей подзадачи отображается только как контекст, не как лишний результат фильтра.

#### R05. Что сохраняется при переходах?

**Рекомендую:** между проектами/метками сохранять период и вид «Список / Календарь». Общие пункты боковой панели явно сбрасывают проект/метки и выбирают свой период. Активные фильтры видны рядом с заголовком и сбрасываются отдельным действием. Подсветка навигации соответствует реально выбранному контексту.

#### R06. Как работает поиск?

**Рекомендую:** поиск сначала по текущему контексту, с понятной командой «Искать во всех задачах». Название и заметка участвуют в поиске; совпадение в подзадаче показывает родителя как контекст. Поиск не запускает фокус и не меняет текущую сессию. Escape очищает запрос или возвращает к предыдущему экрану.

#### R07. Где находятся просроченные разовые дела и недельные дела без дня?

**Рекомендую:** в «Сегодня» показывать отдельные группы «Ранее запланировано» и «Можно на этой неделе», затем сегодняшние дела. Разовые дела не исчезают после прошедшей даты. Невыполненные повторы прошлых периодов остаются в истории и не создают долг.

#### R08. Нужен ли отдельный крайний срок?

**Рекомендую:** основной видимый параметр — «День», то есть план работы. Необязательный крайний срок можно раскрыть в дополнительных параметрах. Перенос дня не меняет срок. Это расширение относительно явно выбранного планирования по дням; в первом простом макете поле срока может быть скрыто до раскрытия.

### Календарь

#### R09. Как период сочетается с месячной сеткой?

**Рекомендую:** сетка остаётся месячной, период определяет видимые задачи. «Сегодня»/«Завтра» выделяют соответствующий день, неделя — диапазон, месяц — текущий месяц. «Все» показывает все подходящие задачи внутри видимого месяца; соседние месяцы доступны навигацией, а подпись месяца всегда видна.

#### R10. Что делают стрелки месяца при активном «Сегодня»?

**Рекомендую:** переход к другому месяцу явно переключает период на этот именованный месяц, например «Декабрь 2026». Нельзя оставлять подпись «Сегодня», показывая другой месяц. Кнопка «Сегодня» возвращает текущую дату и соответствующий фильтр.

#### R11. Чем отличается нажатие даты, задачи и пустого места?

**Рекомендую:** дата открывает список её дел; задача — свои детали; явная кнопка «+» внутри дня открывает создание с этой датой. Создание не должно происходить от случайного одиночного нажатия на пустую область.

#### R12. Как устроены «Ещё N» и детали дня?

**Рекомендую:** показывать несколько компактных задач и «Ещё N» с точным числом скрытых. Полный день открывается в той же правой области, что детали задачи; выбор задачи заменяет список дня и даёт возврат к нему. Дополнительную четвёртую колонку не создавать.

#### R13. Где дела без даты и «раз в неделю в любой день»?

**Рекомендую:** рядом с календарём — сворачиваемая область «Без даты», отдельно — «На этой неделе · день не выбран». Последние не копируются в каждый день. Их можно выполнить сразу или назначить конкретный день допустимой недели.

#### R14. Как переносить дела в календаре?

**Рекомендую:** перетаскиванием между днями и через выбор даты в деталях — оба способа равнозначны. Для повтора обычный перенос меняет только выбранное выполнение; расписание серии редактируется отдельно. После переноса показывать короткое подтверждение с отменой. Выполненный исторический факт переносом плана не переписывается.

#### R15. Какую дату подставлять при создании?

**Рекомендую:** конкретный выбранный день, «Сегодня» или «Завтра» дают точную дату. В общем списке, неделе или месяце без выбранного дня — «Без даты», а не произвольный день. В проекте подставляется проект, в контексте метки — метка. Всё видно до сохранения и редактируется.

### Список и детали

#### R16. Как не перепутать выбор, выполнение и запуск?

**Актуальная компоновка:** название выбирает задачу, круг отмечает выполнение, кнопка инструментов открывает меню Таймер / Помодоро / Секундомер, стрелка раскрывает детей. Нажатие строки не запускает часы. У действий есть подписи/подсказки и отдельные области нажатия.

#### R17. Что показывать справа в компактной строке?

**Рекомендую:** счётчик подзадач, если они есть; при необходимости компактное фактическое время фокуса. Количественных целей и «4/10 страниц» в MVP нет. Не выводить дополнительно все параметры профиля и полную статистику. Метки показывать максимум двумя компактными элементами, остальные — «+N».

#### R18. Как окно приспосабливается к ширине?

**Рекомендую:** широкое окно — боковая панель, рабочая область и детали справа. При нехватке места детали становятся отдельной страницей с «Назад»; фильтры и место в списке сохраняются. Боковая панель скрывается вручную или по явной кнопке. Не превращать детали задачи в модальное окно поверх списка.

#### R19. Какой окончательный порядок деталей?

**Актуальная компоновка:** заголовок/действия, метки, параметры Расписание / Проект / Инструменты, подзадачи, заметка и история запусков по текущей правой панели. В создании Note показана перед подзадачами. Поле Приоритет присутствует, его бизнес-правила уточняются. Значения параметров открывают небольшие редакторы; управление сессией остаётся в нижней панели. Блока количественной цели/ручного количества/недельных отметок нет.

#### R20. Как сделать заметку удобной и надёжной?

**Рекомендую:** редактирование на месте, форматирование появляется по выделению или команде редактора. Пустая заметка — «Добавить заметку», длинная может сворачиваться после нескольких строк. Автосохранение локально; при ошибке текст остаётся в редакторе и есть повтор сохранения. Закрытие деталей не теряет введённое.

#### R21. Что видно у выполненного родителя с открытой подзадачей?

**Рекомендую:** оставлять компактную группу «Родитель выполнен · 1 подзадача открыта». Родитель не выглядит невыполненным, ребёнок остаётся доступен. Активный ребёнок дополнительно виден в панели сессии и моноброви. В календаре используется день этого выполнения, без создания отдельного независимого расписания.

### Создание, проекты и метки

#### R22. Какие поля обязательны и как сохранять новую задачу?

**Рекомендую:** обязательно только название; расписание, проект, метки, note, дети и инструменты необязательны. Создать явно сохраняет задачу; Enter в заметке создаёт новую строку. Закрытие не теряет черновик молча: текущий макет хранит его в памяти; долгосрочное хранение/восстановление уточняется при реализации. Настроек количественной цели нет.

#### R23. Как добавлять подзадачи в этой форме?

**Рекомендую:** список подзадач с быстрым вводом названия и возможностью раскрыть свои заметку, метки и помодоро до создания родителя. Проект и повтор наследуются, настройки таймера отмечены «Как у родителя» или «Свои». Для первого макета — один уровень вложенности.

#### R24. Как создавать и оформлять проект?

**Рекомендую:** название обязательно, небольшой цветовой маркер необязателен. Проект доступен сразу при выборе в задаче и в боковой панели. Он показывает количество открытых дел и сводку результата за период. Не добавлять ему собственный помодоро, чекбокс выполнения или обязательную дату окончания.

#### R25. Что означает архив проекта?

**Рекомендую:** убрать проект и его дела из активных списков, сохранив их в архиве и отчётах; будущие повторы не выводить до восстановления. Восстановление возвращает актуальный период без накопления долгов. Если внутри есть активная сессия, сначала явно закончить её; архивирование не останавливает работу молча.

#### R26. Как управлять метками?

**Рекомендую:** общий список, поиск при назначении, создание по названию, необязательный цвет. Одинаковые названия с разным регистром не создавать случайно повторно. Переименование обновляет отображение везде. Удаление метки убирает связь, но не задачи и результаты; действие допускает отмену. Фильтры показывают изменения явно.

### Повторы, цели и завершение

#### R27. Как показывать время родителя и детей без количественных целей?

**Рекомендую:** показывать фактическое время «На задаче» и «С подзадачами» в истории/отчёте. Это учёт уже отработанного времени, а не цель. Ничего не заполняется вручную в страницах/разах/целевых минутах; количественные цели и их наследование отложены после MVP.

#### R28. Какие правила повторения показать?

**Рекомендую:** «Не повторять», ежедневно, будни, выбранные дни, каждые N дней/недель, ежемесячно, раз в неделю в любой день. Сначала простой выбор, подробности раскрываются ниже. Для 31-го числа в коротком месяце рабочая рекомендация — последний существующий день, с явной подписью правила. Новые варианты являются расширением базового согласованного набора.

#### R29. Что редактируется в серии?

**Рекомендую:** дата переноса и отметка выполнения относятся к одному выполнению; изменение расписания предлагает «Этот и будущие». Прошлые фактические результаты не переписываются. Общая заметка, проект и метки относятся к самой задаче: их изменения применяются ко всем её повторам согласно согласованным правилам.

#### R30. Как заканчивается недельное выполнение без дня?

**Рекомендую:** неделя — понедельник–воскресенье. Одно выполнение можно назначить на день своей недели. После конца периода — «Не выполнено»; явная команда — «Пропущено». Следующая неделя получает новое открытое выполнение. Активная сессия старого периода не теряется и не засчитывается в новое выполнение автоматически.

#### R31. Что делать с ручным «Готово» и отменой?

**Рекомендую:** ручное «Готово» завершает выбранное выполнение и сохраняет его точное время отметки. Отмена открывает это выполнение, сохраняет уже отработанное время и не запускает таймер. Количественная цель для завершения не требуется и в MVP не задаётся.

### Таймер и профили

#### R32. Где запускать фокус и что делать при занятом таймере?

**Актуальная компоновка:** меню инструментов в строке и запуск из деталей; свободный запуск без задачи сохраняется. Все используют единую блокировку: при работающей, приостановленной или отдыхающей сессии новый запуск недоступен, есть К текущей задаче. Просмотр другого дела не перепривязывает минуты.

#### R33. Как показать профиль и собственные параметры задачи?

**Рекомендую:** пресет 25/5/15 после 4, выбор сохранённого профиля, затем «Свои настройки». Подзадаче доступно «Как у родителя» и возврат к наследованию. Текущая сессия использует параметры своего запуска; изменения относятся к следующим. Звуки фокуса/отдыха и громкость вынести в настройки приложения, фоновый звук — в дополнительный блок.

#### R34. Как вести ранний отдых?

**Рекомендую:** сохранить уже отработанную часть, оставить остаток незавершённого интервала и показать его во время отдыха. «К работе» возвращает этот остаток. Ранний отдых не даёт полного помодоро. Части учитываются в фактическом результате один раз; последующее сохранение не повторяет предыдущие части.

#### R35. Как считать цикл между задачами и при новом N?

**Рекомендую:** общий счётчик полных интервалов между задачами. Новое N действует после следующего полного фокуса, не вмешиваясь в текущий. Если порог уже накоплен, заранее показать «Длинный отдых после следующего фокуса». Новый цикл начинается после предоставленного длинного отдыха или его явного пропуска; доступен ручной сброс.

#### R36. Что именно делает изменение времени?

**Рекомендую:** применять выбранное приращение к остатку, сохраняя работу/паузу и владельца сессии. Предпросмотр показывает новый остаток, минимум ноль; приращение можно повторять. Сокращение непосредственно до нуля — ручное окончание с фактом времени, без полного помодоро и автоматических переходов. Это не редактирование длительности в профиле.

#### R37. Какие команды различаются визуально?

**Рекомендую:** Пауза временно останавливает отсчёт, Стоп сохраняет факт и освобождает сессию, Выполнить дополнительно завершает её задачу. Простую остановку сопровождать сообщением о сохранённом времени. Удаление имеет подтверждение по последствиям; закрытие черновика не должно терять введённое. Текущий макет сохраняет черновик в памяти, долговременное поведение уточняется.

#### R38. Что происходит при естественном окончании и автозапуске?

**Рекомендую:** сохранить интервал и перейти в ожидание отдыха либо начать его, если включён Auto Break. После отдыха — ожидание фокуса либо Auto Next Focus на том же деле. Auto Next не пропускает ещё не начатый отдых. Ручная кнопка «Пропустить отдых» может начать следующий фокус. Пока цикл открыт, другая сессия не запускается.

#### R39. Что считается полным помодоро и как избежать повторных результатов?

**Рекомендую:** один логический фокус, дошедший до нуля естественно после явных изменений остатка, даёт один полный интервал. Паузы и ранние отдыхи его не размножают; ручной Stop/сокращение до нуля — частичная работа. Количество интервалов и реальные минуты — отдельные показатели. Естественный конец и последующий Stop не сохраняют одни минуты дважды.

#### R40. Окончание помодоро автоматически выполняет задачу?

**Рекомендую:** нет. Окончание фокуса сохраняет фактическое время, а задачу пользователь выполняет отдельным действием. Блок количественного прогресса и автозавершение по нему исключены из MVP. Автоматический следующий фокус уже выполненного дела не запускается; работу над завершённым делом можно продолжить только явно.

#### R41. Что происходит при скрытии окна, выходе и восстановлении?

**Рекомендую:** закрытие основного окна скрывает его, сессия остаётся доступной в моноброви/меню. Явный выход из приложения сохраняет состояние и завершает работу процесса; при следующем запуске восстановление на паузе без начисления фонового времени. Сон/блокировка также дают паузу. При восстановлении объяснить, почему отсчёт не идёт.

### Монобровь

#### R42. Как выглядит панель без сессии?

**Рекомендую:** без сессии не занимать место дополнительными цифрами; при наведении доступны «Начать фокус» с выбором профиля и «Открыть Focus». При активной сессии сохраняется принятая трёхуровневая компоновка. У ребёнка путь «Родитель › Подзадача» помогает понять владельца, длинное название сокращается с раскрытием полного текста.

#### R43. Как сделать hover и изменение времени устойчивыми?

**Рекомендую:** при переходе курсора из панели в меню приращения панель остаётся раскрытой; небольшая задержка закрытия предотвращает случайное схлопывание. Меню показывает −20…+20, шаг, пресеты, текущий и будущий остаток, «Применить». Escape закрывает меню без применения; управление доступно по нажатию и клавиатуре.

#### R44. Что делать на экране без выреза и с несколькими мониторами?

**Рекомендую:** предусмотреть меню в строке macOS с теми же командами и компактной раскрываемой панелью. На дополнительном экране не запускать второй таймер и не дублировать управление сразу несколькими всплывающими панелями. Поведение при выборе активного экрана показать отдельным состоянием; конкретный механизм платформы решается при реализации.

### Отчёт и сохранность факта

#### R45. Как устроен отчёт и где точные времена?

**Актуальная компоновка:** отдельный экран из боковой панели с периодом день/неделя/месяц и фильтрами проекта/меток/инструмента. Сверху итоги и разбивка трёх инструментов; ниже Сводка / Хронология, в сводке группировка по задачам / проектам / инструментам. Хронология показывает границы и вид инструмента, отметки выполнения без выдуманного времени. Общий недельный отчёт сохраняется, недельная полоса отметок в карточке исключена.

#### R46. Какие итоги не должны удваиваться?

**Рекомендую:** отдельно показывать завершённые задачи, подзадачи, полные помодоро и фактическое время фокуса. Время родителя — сумма прямой работы и детей; общий итог складывается из исходных отрезков один раз. Одна задача с двумя метками видна в обоих фильтрах, но итог их объединения не удваивает её время.

#### R47. Как учитывать полночь, старый план и смену классификации?

**Рекомендую:** минуты распределять по фактическим дням работы, завершение учитывать по моменту отметки. Работа 23:50–00:10 даёт по 10 минут каждому дню. Плановый день не переписывается. Для стабильности сохранять исторические календарные границы; проект/метки, в отличие от времени, используются актуальные, как уже согласовано.

#### R48. Можно ли менять историю и удалять задачи?

**Рекомендую:** отменять ручное выполнение без придуманной длительности. Удаление задачи сохраняет её результаты; показывается последняя известная подпись и доступна отмена удаления. Изменение/исключение ранее синхронизированного фокуса — отдельное расширение после MVP, не скрытое требование простого обмена результатами.

### Удобство и состояния

#### R49. Какие действия должны работать с клавиатуры?

**Рекомендую:** поиск, создание, переход по задачам, раскрытие детей, открытие деталей, запуск/пауза текущего фокуса и возврат к списку. Подсказки сочетаний видны в меню. Не перехватывать обычный пробел и Enter при вводе заметки. Все hover-действия имеют доступный способ нажатия, фокус виден, статус передаётся не только цветом.

#### R50. Что показывать при пустом списке, ошибке и отсутствии сети?

**Рекомендую:** различать «Задач ещё нет», «Нет задач за этот период», «Фильтры ничего не нашли» и «Не удалось сохранить». Предлагать соответствующие создание, смену периода, сброс фильтров или повтор. Отсутствие сети не блокирует локальную работу; статус очереди не занимает главный экран большим предупреждением. Аккаунт доступен из настроек: гость, вход/регистрация, подтверждение email, восстановление доступа и предложение переноса гостевых данных. Необходимость входа для отправки результатов не перекрывает локальный таймер; чужие аккаунтные данные не показываются.

#### R51. Какие предпочтения сохраняются и как использовать анимации?

**Рекомендую:** сохранять ширину/видимость боковой панели, вид, фильтры, раскрытые подзадачи и контекст возврата. Основной макет тёмный по принятому направлению; светлая тема не считается уже согласованным отдельным требованием. Анимации короткие и не мешают таймеру; учитывать уменьшение движения и увеличение текста. Не скрывать ключевые действия только ради чистого скриншота.

#### R52. Какие макеты нужны для первой передачи?

**Рекомендую:** сначала восемь основных композиций: список с навигацией; детали родителя; детали ребёнка; календарь; создание; активный фокус; отчёт; настройки. Монобровь и меню приращения — обязательный отдельный лист состояний. Затем показать ошибки, пустые состояния и переходы, а не рисовать новый экран для каждого варианта данных.

## 4. Передача в реализацию

Основные входы — [MVP](../MVP.md), [принятый дизайн v1](steady-focus-design-baseline.md) и этот подробный разбор. Раздел 1 задаёт подтверждённую основу; R01–R52 дают рабочее поведение в оставшихся ситуациях в пределах MVP. Для деталей использовать принятый макет и порядок R19; флаг приоритета и напоминания из референса не становятся новыми требованиями автоматически.

Дизайн должен позволять проверить путь: выбрать проект/период → создать задачу с подзадачами и note → выбрать день → запустить фокус → добавить время из окна или моноброви → сохранить результат → увидеть точные время и выполнение в отчёте. Детали можно просматривать независимо от владельца таймера.

Состав первой реализации закреплён в обновлённом MVP; открыты перечисленные там технические решения. Этот документ не добавляет синхронизацию активного таймера, напоминания, Fit, социальные механики или новый backend-контракт исправления истории.
