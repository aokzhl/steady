# Steady — актуальные требования к общим задачам и инструментам времени

Дата передачи: **2026-11-10**. Актуализировано по пользовательскому макету: **2026-11-11**.

**Текущая визуальная основа:** `steady-tasks-projects-refined.html`. Обновление от 11 ноября заменяет указания о трёх отдельных кнопках, периодах в боковой панели и старом основном HTML. В строке одна кнопка открывает меню Таймер / Помодоро / Секундомер. Прежние варианты не нужно восстанавливать вместо текущего пользовательского макета.

**Последнее уточнение объёма:** пользователь подтвердил «пока в MVP тренировки не включаем, только задачи». Текущий дизайн — общие задачи с обычными проектами, метками, подзадачами, note, повторами, дневным календарём, необязательными инструментами и отчётами. Тренировочные экраны, программы/упражнения и выбор специализированных типов проектов не показывать как часть MVP.

Документ содержит последние решения пользователя после макетов от 7 ноября. Для перечисленных ниже вопросов он имеет приоритет над старым заданием `reference/steady-focus-design-handoff.md` в проекте дизайна. Текущие HTML и ручные правки пользователя сохраняются; этот файл передаёт требования для последующей итерации, а не утверждает, что новые экраны уже нарисованы.

## 1. Название и текущая цель

- Приложение называется **Steady**. Это единое приложение с общими задачами, проектами, календарём и историей.
- Сейчас приоритет — **общие задачи и общий учёт результатов**, доступный независимо от направления проекта.
- Focus/помодоро — один из инструментов внутри Steady. Тренировки и исламское направление в дальнейшем развиваются внутри приложения, через специализированные возможности проектов.
- Ислам — одна из возможностей продукта, не назначение всего приложения. Имя Amal не выбрано.

## 2. Общие задачи и навигация

- Скрываемая боковая панель: поиск, Все задачи, Отчёт, проекты и метки. Все / Сегодня / Завтра / Ещё → Эта неделя, Этот месяц / Выполненные находятся над списком, рядом метки и Список / Календарь.
- Список сгруппирован по проектам; задачи без проекта и просроченные доступны отдельно. Создание и детали открываются правой панелью; расписание объединяет день и повтор. Приоритет виден в макете, его влияние на сортировку не утверждено.
- Общие разделы объединяют дела всех проектов. Проект, общий список и календарь показывают одни выполнения, а не независимые копии.
- Сохраняются проекты, глобальные метки, заметки, повторы и подзадачи по предыдущим требованиям; выбранный проект не нужно повторять в каждой строке.
- Нажатие названия открывает детали, чекбокс выполняет дело, стрелка раскрывает детей. Эти действия не запускают инструменты времени.
- Задачу можно создать, запланировать и выполнить без измерения времени. При обычной отметке сохраняется момент выполнения, без выдуманной длительности.

## 3. Меню трёх необязательных инструментов

**В текущем макете рядом с каждой задачей одна кнопка, открывающая меню Таймер / Помодоро / Секундомер.** Это относится к любому делу независимо от типа проекта; три отдельные постоянно видимые кнопки не требуются.

| Инструмент | Смысл |
| --- | --- |
| Таймер | Отдельный обратный отсчёт заданного времени |
| Помодоро | Рабочие интервалы с коротким/длинным отдыхом |
| Секундомер | Учёт прошедшего времени со счётом вверх до ручной остановки |

- Инструменты — дополнительные средства, не обязательный этап выполнения задачи и не обязательный выбор при создании.
- Тип проекта не ограничивает доступный инструмент и не назначает его принудительно.
- Смена инструмента не превращает задачу в другой тип и не перепривязывает текущую сессию к просматриваемой задаче.
- Открытие меню само по себе не запускает сессию; пользователь выбирает инструмент. Автоматический выбор по типу проекта не добавляется.
- Вид кнопки и меню брать из текущего макета; сохранять понятные названия, подсказки и доступность с клавиатуры. Полная адаптация на узком окне требует проверки при реализации.
- Детали настройки перед запуском, запоминание параметров и смена инструмента посреди активной сессии требуют отдельной проработки. Не делать вид, что они уже согласованы.

## 4. Общая сессия и обязательная монобровь

- В приложении одна активная сессия занятия, включая паузу и отдых. Запуск второго занятия заблокирован с объяснением и переходом к текущему.
- Окно и монобровь управляют той же сессией. Выбор/редактирование другого дела не меняет владельца.
- Монобровь сохраняется как обязательная часть интерфейса: время/статус в компактном состоянии, раскрытие при наведении, владелец/инструмент и доступные действия. При скрытом окне управление остаётся доступным.
- Действия зависят от инструмента. Пауза/продолжение и Stop общие; отдых и параметры цикла относятся к помодоро. У секундомера нет оставшегося времени.
- Приращение **−20…+20 минут, шаг 1** применяется к обратному отсчёту, с предпросмотром и повтором выбранного приращения. Оно не меняет уже записанную работу и настройки профиля.
- Сохраняются сон/блокировка → пауза, перезапуск → восстановление на паузе, скрытие окна без остановки занятия.
- Окончание инструмента само по себе не выполняет задачу. Stop сохраняет факт; Выполнить владельца дополнительно завершает выбранное выполнение и его сессию. Исключение родитель/активный ребёнок сохраняется.

## 5. Запись времени и отчёт по всем трём инструментам

**Каждое использование инструмента фиксируется, чтобы пользователь видел, что он запускал и сколько времени записано.**

Для записи нужны: вид инструмента, идентичность сессии, задача/конкретное выполнение при наличии, фактические начало/окончание, активное время, паузы/отдых отдельно и причина окончания. Точный контракт данных будет подготовлен при реализации.

- В истории задачи показывать отдельные запуски: какой инструмент, когда и сколько учтено.
- В отчёте день/неделя/месяц есть Сводка / Хронология, фильтры проекта/меток/инструмента, группировка по задачам / проектам / инструментам; работа без задачи также учитывается.
- Последовательные запуски разных инструментов складываются в итог дела. Пример: 10 минут таймером + 25 помодоро + 15 секундомером = **50 активных минут**.
- Паузы и отдых не прибавляются к активному времени. Ранняя остановка сохраняет реальную работу, а не полную плановую длительность.
- Пауза/продолжение не создают новую независимую сессию. Сохранённые отрезки, родитель/дети и несколько меток не удваивают итог.
- Обычный таймер и секундомер не увеличивают число полных помодоро. Полные интервалы и фактические минуты — разные показатели.
- Отметка выполнения без инструмента видна в истории, но не получает искусственной длительности.

## 6. Сохранность результатов

- Результат каждого инструмента сначала сохраняется локально, затем доставляется через устойчивую очередь с UUID и защитой от дубликатов.
- Без сети остаются доступны задачи, таймеры и история. Ожидание входа/доставки не блокирует локальную работу.
- Статусы очереди: ожидание, временный сбой/повтор, требуется вход, ошибка данных. Не занимать основную рабочую область большим постоянным предупреждением.
- Активный таймер между устройствами не синхронизируется. Полная синхронизация задач/планов не добавляется к обмену результатами автоматически.

## 7. Что отложено или ещё не решено

- Специализированные тренировочные показатели: подходы, вес, повторы, собственный прогресс по направлению — **после общего этапа**, пользователь попросил разобрать их позже.
- Весь тренировочный модуль, включая программы, упражнения, специализированный запуск и интерфейс, отложен. Религиозные рекомендации и специальные показатели исламских проектов также не входят в текущую задачу дизайна. В MVP создание обычного проекта не требует выбора типа «Тренировки / Ислам»; не добавлять специализированный мастер даже как обязательную заглушку.
- Полноценный почасовой планнер предложен пользователем, но ещё не проработаны время начала/окончания, длительность, пересечения, дневная/недельная сетка и включение в MVP. Не подменять им согласованную месячную сетку по дням без отдельного решения.
- Напоминания, автоматический запуск по расписанию и внешние календари не согласованы этим обсуждением.
- Количественные цели, +1, полоса прогресса и недельная полоса отметок остаются исключёнными из текущего MVP. Обычные выполнения, расписание повторов, число подзадач и фактическое время сохраняются.

## 8. Текущий макет и последующие изменения

При отдельном запуске доработки дизайна использовать `steady-tasks-projects-refined.html` и учитывать ручные изменения пользователя. `focus-design-options.html` и A/B/C относятся к архиву. Локальный старый экспорт не должен затирать актуальный макет.

Нужные состояния: список с меню трёх инструментов; создание справа и редактор расписания; выполнение без часов; настройка/работа каждого инструмента; пауза/Stop; блокировка второго запуска; монобровь; история нескольких запусков; отчёт с разбивкой и суммой; офлайн/очередь. Наличие демонстрационного состояния не подтверждает готовность нативной функции.

Оформление сохраняет спокойное графитовое направление, сиреневый акцент и компактные отступы. Новые декоративные панели и большие блоки статистики в каждой задаче не нужны.
