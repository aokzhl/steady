# Steady — архив принятого дизайна v1

Дата фиксации: **2026-11-07**. Статус с 2026-11-11: **архив ранее принятой версии**.

Текущая компоновка зафиксирована в [описании обновлённого дизайна](steady-current-design.md) и [локальном снимке от 11 ноября](../../design/steady-focus/current-2026-11-11/steady-tasks-projects-refined.html). В ней одна кнопка меню инструментов, периоды над списком и правая панель создания. Реестр и размеры ниже описывают историческую v1; при расхождении актуальны MVP и текущий дизайн. Снимок от 7 ноября сохранён без изменений.

**Название уточнено 2026-11-09:** приложение называется Steady; Focus — инструмент внутри него. По [ADR-0008](../adr/0008-unified-steady-and-project-types.md) тренировки и исламское направление развиваются внутри Steady позже. Принятый снимок сохраняет исторические подписи Focus; новая функциональность этим уточнением в MVP не добавляется.

**Текстовые уточнения 2026-11-10:** у любой задачи доступны три необязательные кнопки Таймер / Помодоро / Секундомер, с общим сохранением результатов и учётом в отчётах. Это позднее уточнение [MVP](../MVP.md) и [обсуждения](steady-unified-projects-discussion.md); снимок от 7 ноября его ещё не отображает и остаётся неизменным. Специализированный прогресс проектов (подходы/вес/повторы и другое) отложен.

Основание: пользователь сообщил «дизайн готов», допустил мелкие недочёты и попросил закрепить дизайн, требования и обновить MVP. Новое исследование вариантов и перерисовка не требуются. Небольшие исправления допустимы при реализации, если сохраняют компоновку, плотность и описанное поведение.

## Источники и приоритет

1. [MVP](../MVP.md) определяет обязательный объём первой версии и исключения.
2. Этот документ фиксирует принятую визуальную основу и правила её использования.
3. [Подробные требования, R01–R52 и состояния](steady-focus-design-handoff.md) объясняют поведение. Рекомендации ассистента используются как рабочие решения там, где MVP не устанавливает другую границу. Историческое авторство ответов сохраняется: пользователь принял результат целиком, а не отвечал отдельно на каждый пункт.
4. [Зафиксированные макеты](../../design/steady-focus/baseline-2026-11-07/focus-design-options.html) и [карта флоу](../../design/steady-focus/baseline-2026-11-07/focus-user-flows.html) задают визуальный ориентир. [Манифест SHA-256](../../design/steady-focus/baseline-2026-11-07/manifest.json) позволяет проверить точные файлы.

Старые варианты в каталоге дизайна и документы исследования — история решений. Функции конкурентов, демонстрационные данные, переключатели сценариев и технические приёмы HTML не становятся требованиями приложения автоматически. При расхождении количества или поведения в демо с текстовыми правилами следует применять правила, а недочёт макета исправлять.

## Что именно закреплено

Сохранён автономный снимок двух HTML, шести превью и двух пользовательских референсов. Он не зависит от доступности локального сервера Open Design. Проект Open Design: `steady-focus-macos-design`, диалог `855851c3-66e8-4508-b787-327dc5b77c22`.

Снимок содержит три компоновки: **A — «Рабочий»** с постоянным инспектором, **B — «Спокойный»** с инспектором после выбора и **C — «Лист задачи»** с отдельной страницей. Пользователь принял текущий комплект без отдельного выбора буквы. Не требуется реализовывать три переключаемые темы интерфейса. Рабочее правило для нативной версии: список и детали справа при достаточной ширине; отдельная страница с возвратом при узком окне. Состояние до выбора задачи может оставаться пустым. Это правило из R18, а не утверждение о выборе пользователем A, B или C.

## Обязательные флоу

- **F1:** контекст проекта/дня → создание → подзадачи/заметки/помодоро до сохранения → задача в списке.
- **F2:** список ↔ месяц → день/Ещё N → детали → перенос одного выполнения без изменения серии; отдельно без даты и недельное дело без дня.
- **F3:** запуск → просмотр другого дела без смены владельца → запрет второго запуска → монобровь → приращение → пауза/отдых/возврат.
- **F4:** Stop и Выполнить различаются; родитель/ребёнок независимы; выполнение без таймера сохраняет только время отметки.
- **F5:** факт → локальная история/отчёт → очередь без сети → повторная доставка; сон/перезапуск → восстановление на паузе.

Перечень экранов и пограничных состояний находится в разделе 3 подробных требований. Не каждый нарисованный переход доказывает готовность нативной функции: HTML хранит данные в памяти, сон и серверная доставка показаны демонстрационными состояниями.

## Границы и допустимые исправления

В MVP входят дневное планирование в месяце, повторы, заметки, подзадачи, отчёт и обязательная монобровь. Количественные цели, напоминания, почасовой календарь и синхронизация активного таймера исключены. Дополнительный крайний срок из R08, расширенные повторы «каждые N»/ежемесячно из R28, библиотека фоновых звуков из R33 и расширенное редактирование синхронизированной истории из R48 остаются после MVP; присутствие в разборе не делает их обязательными.

Без нового обсуждения можно исправлять переполнение, обрезанный текст, неработающие кнопки, контраст, выравнивание, небольшие отступы и соответствие утверждённым правилам. Изменение навигации, модели задач, логики сессии или возвращение исключённого блока требует обновления требований. Мелкие недочёты разрешены пользователем, но конкретный список дефектов этим не объявлен найденным и исправленным.

Снимок `baseline-2026-11-07` не перезаписывается при дальнейших правках. Рабочие HTML могут развиваться отдельно; следующая принятая версия получает собственный снимок. Git-коммит этим документом не подразумевается.
