# Steady — запуск помодоро и секундомера без путаницы

Дата исследования: **2026-11-09**. Статус: исследование и предложение интерфейса; последним уточнением в Q4 принят свободный выбор помодоро/секундомера для любой задачи. Форма выбора, запоминание и предлагаемые defaults этим не утверждены; актуальное решение находится в [обсуждении](../design/steady-unified-projects-discussion.md).

Контекст: [обсуждение единого приложения](../design/steady-unified-projects-discussion.md).
Принятое ограничение: одна активная сессия; тренировочные упражнения, отдых и паузы находятся внутри неё.
Общий список показывает запланированные выполнения обычных, тренировочных и исламских дел.
Этот документ не меняет ADR, GLOSSARY, MVP, прототип или нативный интерфейс.
В [текущем HTML-прототипе](../../design/steady-focus/focus-design-options.html) запуск создаёт стадию `focus`
с обратным отсчётом; описанные здесь секундомер и тренировочное выполнение ещё не реализованы.

## Рекомендация

Предлагается **один основной запуск с видимым текущим режимом и необязательным изменением перед стартом**.
Например: `Начать` рядом с `Режим: Помодоро · 25 мин ▾`; для тренировки — `Режим: Секундомер ▾`.
В плотной строке допустимо `Начать · Помодоро` и отдельный доступный переключатель режима рядом.
Одинокая кнопка `▶` или `Начать`, молча запускающая сохранённый режим, делает результат непредсказуемым.
При выборе режима до запуска меняется настройка и подпись; сама сессия начинается только по `Начать`.
Это проектная гипотеза на основе источников ниже, а не подтверждённый результат тестирования Steady.

Разделять три понятия: **тип проекта** задаёт доступные возможности; **сценарий выполнения** определяет,
обычное ли это дело или тренировка с упражнениями; **режим таймера** определяет отсчёт вниз или вверх.
Выбор секундомера для тренировки сохраняет её упражнения и отдых. Обычное дело `Купить абонемент`
в тренировочном проекте не должно автоматически открывать тренировочный сценарий.

Источники описывают рекомендации платформы и поведение продуктов. Они **не доказывают**, что участники быстрее
или точнее используют какой-либо вариант Steady. Документация TickTick не подтверждает сохранение режима
на уровне конкретного дела. Документы Hevy не подтверждают точный автоматический замер каждого упражнения.

## Три варианта запуска

| Вариант | Что получает пользователь | Риск и применимость |
| --- | --- | --- |
| Обязательный выбор при каждом запуске | Всегда видит обе команды; нельзя молча применить прежний режим. | Каждый повтор требует решения. Само наличие меню ещё не объясняет смысл режимов. Имеет смысл при действительно неизвестном намерении; влияние на ошибки надо проверить. |
| Две равноправные кнопки | Оба запуска обнаруживаются сразу и доступны одним нажатием. | Занимают место и повторяют выбор в каждой строке; нет явного обычного действия. Подходят для широкого экрана первичного знакомства, если оба варианта одинаково нужны. |
| Основной запуск + видимый сохранённый режим | Обычный запуск — одно действие; другой режим доступен рядом. | Плохой default или незаметный переключатель могут привести к ошибке. Рекомендуется как основной вариант для проверки. |

Если на отдельном экране места достаточно, два сегмента `Помодоро / Секундомер` над одной кнопкой `Начать`
делают выбор явно видимым. Это альтернативное представление той же модели состояния, а не две активные сессии.
Для двух вариантов не обязательно использовать выпадающее меню: компактность и обнаруживаемость проверяются на макете.

## Как выбирать default

Ниже — предлагаемые правила Steady, а не свойства конкурентов или уже принятые решения.

1. Явный выбор пользователя для конкретного дела имеет приоритет над исходной рекомендацией.
2. Для повторяющегося дела выбор сохраняется у самого дела и применяется к его будущим выполнениям;
   запуск из Сегодня, календаря или проекта читает одно состояние. Не создавать разные настройки по точкам входа.
3. Для нового обычного дела можно предложить помодоро: это продолжение текущего обсуждения, которое ещё нужно проверить.
4. Для конкретного занятия/шаблона структурированной тренировки предложить секундомер с этапами. Плановые `45 мин` показывать как оценку;
   они не превращают секундомер в отсчёт, который завершает тренировку по нулю.
5. Не определять режим по одному признаку «исламский проект». Для изучения суры уместно предложить оба режима;
   намаз может быть отмечен выполненным вообще без таймера. При первом намеренном запуске учёта времени
   у дела без понятного default допустим короткий явный выбор с пояснениями, затем сохранить выбранное.
6. Не переносить последний режим на весь проект или весь Steady: выбор секундомера для одной тренировки
   не меняет запуск отчёта или чтения. Явное исключение пользователя не должно перезаписываться новым default.

В выборе дать короткие объяснения: `Помодоро — заданный интервал и перерыв`,
`Секундомер — время вверх до остановки`. Число `25:00` без подписи не объясняет эту разницу.
Если требуется разовый режим без сохранения, обозначить это отдельным явным действием;
не вводить скрытое различие между «выбрал в меню» и «выбрал на другом экране».

## Примеры в смешанном списке Сегодня

| Выполнение | Предлагаемый запуск | Что остаётся понятным |
| --- | --- | --- |
| Подготовить отчёт | `Начать` · `Помодоро · 25 мин ▾` | Перед стартом виден интервал; можно выбрать секундомер. |
| Силовая тренировка A | `Начать` · `Секундомер ▾` | Открывается тренировка с упражнениями; общий счётчик идёт вверх. |
| Повторить суру | `Начать` · `Секундомер ▾`, если он ранее выбран | Исламский проект не заставляет использовать конкретный режим. |
| Аср | `Отметить выполненным`; запуск времени доступен отдельно | Отметка не создаёт фиктивную длительность и не требует таймера. |

Тип проекта и режим — разные признаки. Показывать тип/название проекта и текущий режим текстом,
не полагаться только на цвет или значок. Для намаза это не рекомендация религиозной практики, а пример управления делом.
Если уже идёт эта сессия, показывать `Продолжить`/`Открыть занятие`; выбор режима нового запуска здесь не нужен.
Если активна другая, показать её название и переход к ней; начало нового занятия требует явного завершения текущего.
Не останавливать старую и не открывать вторую незаметно. Смена режима внутри сессии остаётся отдельным решением.

## Тренировка: три показания, одна сессия

Предлагаемая иерархия экрана: `Тренировка · 18:42` и ниже текущий этап —
`Упражнение: присед · 00:36` либо `Отдых · осталось 01:20`.
Общие часы и часы этапа могут идти одновременно: вторые описывают часть первых.
Помодоро, если пользователь выбирает его для тренировки, должно менять управление интервалом той же сессии;
не создавать независимый параллельный результат Focus. Точные переходы между этапами ещё требуют согласования.

- **Время занятия:** отдельно определить полный промежуток от старта до завершения и время без явных пауз;
  подписать выбранное основное показание. Обычный тренировочный отдых входит в занятие, внешняя пауза учитывается отдельно.
- **Время упражнения:** нужен зафиксированный старт и конец этапа/подхода либо явный ручной ввод с такой пометкой.
  Если этап включает подготовку оборудования, так его и называть; это не обязательно чистое время движения.
- **Отдых:** плановый отсчёт помогает ждать, но фактический интервал заканчивается при переходе к следующему этапу.
  Ноль сообщает о завершении плана; он сам по себе не доказывает, что человек перестал отдыхать.
- **Пропуски:** переходы, подготовку и неизвестные интервалы показывать отдельно, а не автоматически объявлять упражнением.

Особенно важно: отметки «подход завершён» — события регистрации. Разность соседних отметок может включать отдых,
подготовку и задержку ввода. По ним одним нельзя обещать фактическую длительность упражнения.
Hevy [6] подтверждает запуск отдыха после отметки, а не эту точность; корректируемая длительность [7] также не доказывает её.

Для отчёта суммировать непересекающиеся интервалы одной сессии: например,
`20 мин упражнения + 15 мин отдых + 5 мин переходы = 40 мин занятия без пауз`.
При ещё `5 мин паузы` полный промежуток равен `45 мин`. Нельзя прибавить к 40 минутам эти же этапы ещё раз.
На общей сводке тренировка даёт один результат; разбивка раскрывает его состав. Оценки и ручные исправления помечаются.

## Обнаруживаемость и клавиатура

Основной запуск и текст текущего режима видны до взаимодействия. Переключатель находится рядом,
имеет название `Режим таймера`, показывает выбранный пункт и открывается обычным нажатием;
длинное нажатие, hover и контекстное меню могут дублировать его, но не быть единственным доступом.
Настройки длительности и циклов раскрываются по необходимости по принципу [4].
Первое знакомство объясняет два режима одной строкой, а не обязательным повторяющимся диалогом.

Для будущей реализации предложены: последовательный Tab-фокус «режим → запуск», стандартные клавиши выбора
в меню, Escape для закрытия без старта, Space для активации сфокусированной кнопки.
Return запускает явно выбранное дело только в контексте его экрана запуска; не перехватывать ввод в редакторе задачи.
Доступное имя кнопки включает действие и режим, например `Начать отчёт, помодоро, 25 минут`.
Это требования к проверке доступности будущего интерфейса, не утверждение о готовой реализации.

## Небольшая проверка гипотезы — ещё не проведена

Провести модерируемые сессии с 6–8 людьми, знакомыми с задачами, но с разным опытом таймеров;
включить людей, регулярно записывающих тренировки, и пользователей с релевантными исламскими делами.
На одинаковом наборе Сегодня сравнить три интерактивных макета; менять порядок вариантов между участниками.
Не подсказывать термин режима в инструкции: «поработайте 25 минут с перерывом», «измерьте длительность без окончания по плану».
Затем: повторный запуск сохранённого дела, другое дело после тренировки, исправление неожиданного режима,
возврат к активной тренировке, переход упражнение → отдых и запуск только клавиатурой.

Записывать выбранный режим, предсказание поведения до старта, ошибочные запуски и исправления,
время/действия до корректного запуска, обнаружение альтернативы и понимание общего времени против этапов.
Отдельно проверить, считают ли люди ноль отдыха фактическим концом отдыха и понимают ли отметку без таймера.
Сравнивать наблюдения по сценариям; маленькая выборка не даёт основания объявлять статистическое превосходство.
Если сохранённый режим систематически пропускают взглядом, сначала усилить его подпись/видимость,
затем проверить сегменты; обязательный выбор оставлять гипотезой для сценариев с неясным намерением.
