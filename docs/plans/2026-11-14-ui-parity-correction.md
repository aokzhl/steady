# Возврат к принятому интерфейсу Steady

14 ноября пользователь указал на существенные расхождения реализации UI/UX с макетом OpenDesign. Затем отдельно подтвердил: эталон — `steady-tasks-projects-refined.html` от 11 ноября, а не более новая версия.

Источник — неизменённые HTML, manifest и скриншоты в `design/steady-focus/current-2026-11-11/`. Поведение по-прежнему определяется MVP, действующими ADR и уже принятыми ответами пользователя, включая приоритет «Без приоритета» по умолчанию и долговременный черновик. Новая компоновка не меняет модель данных или границы MVP.

Сначала привести к этому эталону основное окно, список, создание и детали: размеры и расположение областей, плотность, типографику, строки свойств, иерархию подзадач, закреплённые действия и возврат в узком окне. Затем интегрировать подготовленные календарь и профили в тот же интерфейс. Их функциональные проверки сами по себе не означают визуальную приёмку.

До визуальной проверки не сливать подготовленные UI-срезы #13 и #19. Сопоставлять запущенное приложение с макетом при одинаковом логическом размере окна и на соответствующих экранах. Нативную проверку выполнять через CUA на отдельных тестовых данных; существующие проверки публичного TaskWorkspace с временной SQLite сохраняются. Функциональные пробелы обозначать явно, не заменяя их неработающими контролами.

Остальные локальные задачи остаются в работе. Настоящие сон/блокировка для #18 отложены пользователем; API по-прежнему не входит в текущий цикл.
