# Микросервисы и принадлежность данных продуктам

**Уточнение 2026-11-09:** [ADR-0008](0008-unified-steady-and-project-types.md) объединяет клиентские возможности в приложении Steady. Решение о микросервисах и отдельных базах сохраняется. Упоминания самостоятельных Focus/Fit ниже исторические; принадлежность данных будущих типов проектов уточняется отдельно.

Backend Steady будет состоять из микросервисов. Цель — независимо развивать, обновлять и развёртывать продукты, по возможности ограничивая влияние изменений и сбоев одного продукта на другой. Пользователь выбрал этот подход вместо предложенного единого приложения FastAPI с внутренними модулями.

В MVP выделяются sso (аккаунт Steady и авторизация) и Focus (функции приложения Focus). sso реализуется самостоятельно на FastAPI: пользователь выбрал собственный сервис вместо готового сервера авторизации. Вход по email и паролю и самостоятельная проверка токенов доступа в Focus описаны в [ADR-0006](0006-sso-login-and-access-tokens.md).

Каждый сервис владеет отдельной базой PostgreSQL, пользователем базы и миграциями. На старте допустим один экземпляр PostgreSQL для этих баз: это проще в обслуживании, но сбой экземпляра затрагивает оба сервиса. Сервисы не читают таблицы друг друга; способ взаимодействия через API ещё не выбран.

Задачи, профили помодоро и результаты рабочих сессий принадлежат Focus. Программы тренировок, упражнения и подходы относятся к будущему Fit. Общий аккаунт объединяет пользователя экосистемы, а будущий обзор собирает показатели разных продуктов, сохраняя их собственный смысл.

Реализуем сейчас Focus; разработка сервисов Fit отложена до начала работы над этим приложением. Микросервисы требуют отдельных процессов и настройки их взаимодействия, запуска и обслуживания; подробности эксплуатации ещё не выбраны.
